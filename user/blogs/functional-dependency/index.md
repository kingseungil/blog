# 데이터베이스의 함수적 종속성 이해하기

안녕하세요, 오늘은 데이터베이스 설계에서 중요한 개념인 함수적 종속성에 대해 알아보겠습니다. 이 개념들은 효율적인 데이터베이스 구조(정규화)를 만드는 데 핵심적인 역할을 합니다.

## 1. 함수적 종속 (Functional Dependency)

| 학번   | 이름  | 학과    |
|------|-----|-------|
| 1001 | 김철수 | 컴퓨터공학 |
| 1002 | 이영희 | 경영학   |
| 1003 | 박지민 | 물리학   |

함수적 종속은 한 속성(또는 속성 집합)의 값이 다른 속성의 값을 유일하게 결정할 때 발생합니다.

**예시:**
- 학생 테이블에서 '학번'이 '이름'을 결정합니다.
- 표기법: 학번 -> 이름 (학번이 이름을 결정한다)

## 2. 완전 함수적 종속 (Full Functional Dependency)

| 주문번호 | 제품번호 | 주문수량 |
|------|------|------|
| O001 | P101 | 5    |
| O001 | P102 | 3    |
| O002 | P101 | 2    |
| O002 | P103 | 1    |

완전 함수적 종속은 속성 집합 전체가 다른 속성을 결정하는 경우를 말합니다. 이때 속성 집합의 어떤 부분집합으로도 그 속성을 결정할 수 없어야 합니다.

**예시:**
- '주문' 테이블에서 `{주문번호, 제품번호}` -> 주문수량
    - 주문번호와 제품번호를 모두 알아야만 주문수량을 알 수 있습니다.
    - 주문번호만으로는 주문수량을 알 수 없고, 제품번호만으로도 알 수 없습니다.

## 3. 부분 함수적 종속 (Partial Functional Dependency)

| 학번   | 과목코드  | 학과    | 성적 |
|------|-------|-------|----|
| 1001 | CS101 | 컴퓨터공학 | A  |
| 1001 | CS102 | 컴퓨터공학 | B  |
| 1002 | BZ201 | 경영학   | A  |
| 1003 | PH301 | 물리학   | B  |

부분 함수적 종속은 속성 집합의 일부분이 다른 속성을 결정하는 경우입니다.

**예시:**
- '수강' 테이블에서 `{학번, 과목코드}` -> 학과
    - 학번만으로도 학과를 알 수 있습니다. (학번 -> 학과)
    - 이 경우 `{학번, 과목코드}` -> 학과는 부분 함수적 종속입니다.

## 4. 이행적 함수적 종속 (Transitive Functional Dependency)

| 사원번호 | 부서코드 | 부서장 |
|------|------|-----|
| E001 | D10  | 김부장 |
| E002 | D10  | 김부장 |
| E003 | D20  | 이부장 |
| E004 | D30  | 박부장 |

이행적 함수적 종속은 A -> B이고 B -> C일 때, A -> C가 성립하는 경우를 말합니다.

**예시:**
- '직원' 테이블에서
    1. 사원번호 -> 부서코드
    2. 부서코드 -> 부서장
    3. 따라서, '사원번호 -> 부서장'이라는 이행적 함수적 종속이 발생합니다.

## 정리

함수적 종속성을 쉽게 이해하기 위해 다음과 같이 요약할 수 있습니다:

- **함수적 종속**: "이것을 알면 저것도 알 수 있어!"
- **완전 함수적 종속**: "이것들을 모두 알아야만 저것을 알 수 있어!"
- **부분 함수적 종속**: "이것들 중 일부만 알아도 저것을 알 수 있어!"
- **이행적 함수적 종속**: "A로 B를 알 수 있고, B로 C를 알 수 있다면, A로 C도 알 수 있어!"

이러한 함수적 종속성 개념들은 데이터베이스 정규화 과정에서 중요하게 사용됩니다. 불필요한 중복을 제거하고 데이터의 일관성을 유지하는 데 큰 도움을 줍니다.

데이터베이스 설계시 이러한 개념들을 잘 이해하고 적용한다면, 더 효율적이고 일관성 있는 데이터베이스 구조를 만들 수 있을 것입니다.
